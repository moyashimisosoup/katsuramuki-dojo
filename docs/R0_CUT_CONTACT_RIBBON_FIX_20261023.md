# APP-022｜R0の刃・薄片・大根の表示を整合させる修正

確認：2026-10-23 JST｜作業範囲：**R0の3D表示と2D代替模式図**。R0切削物理（`src/physics/surface.js`）の変更なし。

## 観察と問題の切り分け

- 添付されていた「R0」と表示された画像は**旧2D模式図**。現在のmainでは通常Three.jsの3Dが起動し、失敗した場合は`src/view/draw.js`の2Dが表示される。「この画像を改善した」ことと「現在のスマホ実機で3Dが動いた」ことは別。
- 旧2Dは大根が直立し、包丁の接点と細線で描かれた帯の始点が違う座標から構築されていた。**旧画像での距離を写真校正済み実寸の誤差と呼ばない**。
- 現行3Dでは`ribbonGuidePoint`の開始点が`bladeRadius + 0.5`となり、**帯の根元が包丁の接触線から0.5モデルmm離れていた**。さらに`buildRibbonMeshData`は刃の傾き`tilt`を受け取らないため、角度調整時に帯の始端の左右が刃と一致しなかった。

## 今回の修正

### 3D表示

- `src/view3d/geometry.js`：帯の開始点を`bladeRadius`の接触位置へ修正。`buildRibbonMeshData(daikon,bladeRadius,{tilt,...})`を追加し、帯の始端2点を`bladeEdgeEndpoints`と厳密に一致させる。
- `src/view3d/scene.js`：その時点の`tilt`を薄片生成へ渡す。
- 薄片は**軸方向の幅を持つ一枚の3Dメッシュ**として描画する。根元が刃から分離して見える問題を除去する。
- ストローク機構、植物組織の撓み、破断、荷重の物理は依然未実装。帯の湾曲は見た目の仮曲線。

### 2D代替

- `src/view/schematic-layout.js`（純粋関数）で、**横向き大根、軸方向を横切る切れ刃、その刃の端から続く幅広い薄片**の共通座標を定義。
- `src/view/draw.js`：旧来の細いストローク表示をやめ、一枚の帯として塗りつぶして描く。帯の上端＝切れ刃の両端。**手は描いていない**ことを明示し、実技姿勢としての誤認を防ぐ。
- `src/main.js`：刃の傾きを2D代替描画にも渡す。WebGLが使えない時は「2D模式図・手指省略」と明示。
- `currentRibbonLength=0`なら、過去に帯が剥けた履歴`ribbonLength`が正でも**新しい帯を描かない**。切断後に不自然な紐が残る状態を抑える。

## 受入基準

1. 3Dの切れ刃と帯始端の2端点が一致：刃の傾き3種類・切削角3種類でテスト。
2. 3D/2Dとも薄片が大根の軸方向幅を保つ。傾斜しても切削線との端点整合が崩れない。
3. 2Dは大根横持ちの**模式図**。実測・手指・包丁の正しい握りの認定ではない。
4. 帯が切れて`currentRibbonLength=0`になった場合は、過去の累積帯の長さにかかわらず帯を描かない。
5. 既存`npm test`と`tools/validate_data.py`が成功、Pagesが必要な新モジュールを配信する。
6. **公開コード／CI／PagesのHTTP到達**と**実機Safariでの3D/2D表示**を分けて報告する。後者を見ていなければ未検証。
