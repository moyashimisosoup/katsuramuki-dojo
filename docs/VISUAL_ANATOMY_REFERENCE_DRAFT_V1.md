## 2. 3Dビジュアルで守るべき現物の構造

1. **大根は皮をむいて切りそろえた短い円柱**で、主観的な大きさは成人の片手で支えられる範囲。長い葉付き大根や固定台・モーターによる自動回転は通常の桂むきの描写として使わない。
2. **左手が大根を直接保持して回転させ、右手が包丁を操作**する。左右手の動きは独立の入力・アニメーションパラメータを持つ。初心者ゲームの「自動回転」は入力補助と明記し、可視の機械式ローラーとして表さない。
3. **包丁の切れ刃の接触線と大根の円筒軸の幾何関係を成立**させる。刃が大根の真ん中へ斧のように刺さる、円柱端面を輪切りする、刃を突き立てたまま帯だけ増える等は不可。角度は写真からの**推定**であって普遍的な固定値ではない。
4. **帯は「細い紐」ではなく円柱の軸方向長さに近い幅を持つ薄い連続シート**。発生点は刃と大根の接触付近。帯の幅、長さ、上下2縁の厚さは別々に持つ。
5. 帯が刃先から生まれ、大根から分離する過程がひと目で追えるようにする。むけた帯は重力で垂れ、折れ・しわ・ゆるい巻きは起きうるが、必ずきれいな同心円に並べない。
6. 桂むきの表面の薄さと透明感は自然光・透過色・両面の薄片表現によって出す。むけた帯の白い色と濡れた質感を保ち、プラスチックのフィルムや紙テープのような質感になりすぎない。
7. 高品質の絵でも、刃が同一の箇所で材料を削らずに帯だけ出る表現は不可。静止画の魅力と、動的な素材保存モデルの一致は別検証。

## 3. カメラを2系統用意する

### CAMERA-A：メインゲーム用
- 調理者の正面斜め上方（手の甲が一部見え、大根の切断面と刃が見える位置）を最初の試作カメラとする。
- 刃先の接触点、短い円柱、左手・右手、帯の入口と最初の落下部分を一画面内に配置。
- 手や説明パネルが刃先を隠さないよう、操作UIを下部や外側へ配置。スマホ縦画面では視界を優先し、情報量を絞る。
- 画面タップ・ドラッグ領域とモデルの観察領域を分けることを検討。

### CAMERA-B：技法／検証用
- 接触点を拡大し、刃の平面、材料の局所変形・除去、帯の上縁と下縁を示す。破断や実際の力学が未実装のときはその演出を「物理的に検証済み」としない。
- 側面ビューまたは断面図で刃先の位置と大根半径の関係を示す。ただし断面図は説明用であり、ユーザーの通常操作画面と区別する。

## 4. モデル化の対象と技術境界

| アセット | 生成方法 | 動的接続 |
|---|---|---|
| 大根（円柱と断面） | Three.jsで生成する可変メッシュ | R0 の角度×幅方向の半径フィールド |
| 和包丁・木柄 | 権利処理済みGLB/自作3D | 接触線と位置・角度を物理コアから反映 |
| 左右の手 | 初期には簡略3D手モデルまたは見せない構図も可 | 手の補間姿勢。物理計算に直接混ぜない |
| 帯（うすいシート） | 軸方向2縁以上、長さ方向に頂点を増やす動的メッシュ | R0の切削帯区間・両縁厚さ。重力・揺れは将来R2 |
| 背景・まな板・光 | 自作または適法ライセンスの3D/テクスチャ | 切削とは独立 |
| UI | Figmaで構造検討 → HTML/CSS | 値は物理コアの状態に連動 |

## 5. 画像生成イメージの検証

画像生成物はスタイル方向の見本であり、寸法や包丁角度、動作の計測値の出所にはしない。読み取れるゲーム内数値は**架空のモック数値**。
- 大根が葉付きのまま鉛直に固定される／回転台がある：一般的な手持ち桂むきとしては不採用。
- 大根を丸ごと輪切りにする描写：不採用。
- 同じ部分を削っていないのに帯だけ無限に出る：不採用。
- 細い帯・紐状の帯：不採用。
- 写真に存在しない刃の角度（例：5度や15～25度）を「正確な標準値」と断定しない。
- UIデザインと写真リアリティを独立して審査。再現可能な動的3Dシーンの受入で最終採否を決める。

## 6. 次の具体的タスク

1. 実物写真から共通する手元の方向・大根の軸・刃の接触線・帯の出口を3D座標で定義。写真の見かけ角度ではなくモデル座標として保存。
2. 背景・手なしの検証シーンで、大根、刃、帯の3オブジェクトを置く。カメラA/Bを切り替えて観察。
3. R0局所切削データから大根の可変メッシュと帯の長さ・幅・厚さへ対応づける。体積保存テストを維持。
4. その後に手モデル、照明、材質、UIを追加。スマートフォンの処理速度と読み取りやすさを検証。
5. **公開前・正式採用前**に実物資料との照合と、ユーザーによる見た目確認を受ける。
