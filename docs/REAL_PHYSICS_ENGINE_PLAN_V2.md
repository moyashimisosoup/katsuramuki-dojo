# 実際の物理現象から作る桂むきエンジン | 研究・実装計画 v2.0

APP-ID: APP-022 / 2026-10-18 JST / 状態: **設計文書、未実装・未校正・未公開**
正本: moyashimisosoup/katsuramuki-dojo
前版: docs/PHASE0_KATSURAMUKI_PHYSICS_PLAN_V1.md
設計目標: 包丁と大根の相互作用が原因となって「材料が削れる→帯が生まれる→変形→必要なら破断」が一貫して成立する。

## 0. 判断要旨

- 物理モデルは（A）大根・包丁の運動、（B）接触と材料除去、（C）切削抵抗と回転応答、（D）生成した帯の柔軟体運動、（E）局所亀裂・破断に分離。
- **最初から汎用剛体エンジンは不要。** 幾何学的切削に独自コア、帯の動きに後から軽量PBD/XPBDを採用する。3D描画用のThree.jsも独立した選択。
- 2023年の桂むき実測研究は「厚さ・上下差・所要時間」の評価指標に使える。ただし大根の材料定数・包丁に作用した切削力は示していないので、力学係数を論文だけで確定しない。
- 接触形状と物体の更新はなるべく幾何学・保存則で厳密にし、素材強度・摩擦・破断は初期は「仮パラメータ」、実測または動画分析で段階的に校正する。
- リアルな物理挙動の検証と「遊んで気持ちよい」入力補助は分離し、物理モードをアーケード調整で偽装しない。

## 1. 観察された現実の動作

1. 大根は手に保持したほぼ円柱形の物体。回転角と姿勢を変えながら表面を刃先に送る。
2. 包丁の刃先は大根の接線方向の近傍で、切削深さ・刃の傾き・上下滑走によって局所的な剥き厚さが決まる。上下ストロークは刃先の**半径方向送りと同一ではない**。
3. 剥かれる帯は大根と同等の幅（大根の軸方向長さ）を持つシート。上端と下端の厚さは一致するとは限らない。
4. 刃が押し込むと大根に弾性変形・局所破壊が起きる。刃先の鋭さ・角度・速度・食材状態により必要な力は変わる。
5. 切り離されたシートは柔らかいが完全な布ではない。曲げ・伸長・引張・局所の裂けに抵抗し、重力で垂れる。
6. 初心者の破断は「極薄だから」だけではない。刃の角度ずれ、切り込み、両手の協調不良による局所欠陥があり得る。

根拠の限界：2と4の定量的な係数は桂むきそのものの直接実測では確立していない。説明は物理モデル化の仮説を含む。

## 2. 何を解くのか：状態と座標

世界座標：zは大根の軸方向（帯の幅方向）、φは大根に固定された円周角、rは中心から表面までの距離。包丁は世界座標の位置・刃の方向と傾きで表す。

物理状態例：
- Daikon: rotation θ, angular velocity ω, axis pose, geometry field R[φ,z], cut mask, density/material profile.
- Knife: blade edge position x, orientation yaw/pitch/roll, contact line, sharpness, up-down sliding speed, virtual hand input.
- Contact: engaged fraction across width, cutting depth h(z), face alignment, relative tangential velocity, required force.
- Ribbon: strip samples (arc length s, width-position z, local thickness t, attachment/contact status), mass, bending/stretch constraints and crack status.
- Diagnostics: removed volume, created ribbon volume, friction work estimate, time-resolved forces, cause-coded failures, solver residual.

初期大根の外形は円柱でもよいが、均一な剥き厚さを前提とせず、**角度×幅方向の2次元表面フィールド**を使う。幅方向の厚さ差を直接作れることが重要。

試験グリッド案：円周方向256区画×幅方向12区画の浮動小数点フィールド。物体変形の絶対精度を主張する値ではなく、実装の初期比較条件。128/256/512の収束試験で最終決定。更新時には回転区画をまたぐ接触をスイープし、1フレームの高速回転で切削対象を飛ばさない。

## 3. 接触・幾何学切削（Phase R0）

各固定ステップで刃先の掃引位置を計算し、接触する表面フィールドの対象セルを調べる。現在の材料表面を r_old(φ,z)、刃による新しい表面の候補を r_blade(φ,z) として、

    r_new(φ,z) = min(r_old(φ,z), r_blade(φ,z))  // 切削が成立し、下限半径より外側の場合
    t_local(φ,z) = max(0, r_old(φ,z) - r_new(φ,z))
    dV = 0.5 * (r_old² - r_new²) * dφ * dz

局所接触しない区画、反転中や刃が離れた区画はそのまま残す。刃の傾きは刃先の半径位置がzによって変わる項（例えば r_blade(z)=r0+a(z-zc)）として表現し、幅方向に厚い/薄いを再現。刃を動かしていないとき、勝手に大根が痩せることはない。角度変化だけで削る場合も、材料と刃との幾何学的交差があるときに限定。

**従来v1での簡易式の限界（重要な修正）**
- 「1回転で半径がf減少」は、刃を実際に半径方向へ送り込む特定の操作軌道の近似にすぎない。一般に回転だけでは半径が一様に減らない。
- 「1回転の削除体積がπW(R0²-R1²)」は、全周に一様な半径R1の表面ができた場合の式。**初回の螺旋状の切削では全周が均一に減らない**ため、そのまま使うと削除体積を過大評価することがある。
- 初回の剥き始めと2周目以降は材料表面履歴が異なるため、接触厚み・最初の帯の形成を別のテストにする。最初は大根外周に開始切り込み/タブを準備した状態をUIで明示してもよい。
- v1の半径・帯長式は理想円柱・一様切削の**比較基準**にとどめ、現実寄りのエンジンの真値としない。

単純化して円柱の均一な1周を全削除したときだけ、V=πW(Rbefore²-Rafter²)が参照解になる。部分回転では区画積算 dV を使う。

帯の長さは剥離前の局所円周弧長 dL≈r_contact*dφ を主とし、幅方向に厚さ/切削長の差がある場合は両縁の座標も持たせる。幅方向全体が接触していないと「帯全面の長さ」として加点しない。

## 4. 力と抵抗（Phase R1）

コンセプト：包丁には材料を切り離すための仕事、切断前の圧縮/変形、摩擦、刃の鈍さによる抵抗が作用する。

初期の縮約モデルの形：
    F_required = F_fracture(W, thickness, material) * edgeFactor(sharpness, bevel, contact)
               + F_friction(normalLoad, slidingVelocity, moisture)
               + F_ploughing(penetration, bladeGeometry)

これらは**関数の形を先に定義するだけ**であり、N（ニュートン）単位を与える具体的な係数は計測後に確定する。必要な切断仕事と切断面積との対応を寸法解析で確認。単純な速度増大=必ず抵抗増大とは断定しない。摩擦や滑走の向きによる違いを別に扱う。

ユーザーの入力は力センサーではないため、realistic modeは指のドラッグを「仮想手トルク指令」や「刃の位置指令」に変換する。その違いをゲーム設定と説明文に明記。手側の力の上限を設定する場合のみ、

    I*dω/dt = τ_hand - R_eff*F_tangential - c*ω

で回転の失速を再現する。ここでF_tangentialは刃から大根回転へ逆らう実効接線力。指の位置をそのままニュートン単位として扱わない。

理想化（物理）と操作補助（ゲーム）を別コンポーネントとし、同じ入力列で同じ結果を再現できるようにする。

## 5. 薄い帯の力学（Phase R2）

「細い紐」ではなく、**幅のあるシート**を生成する。最初は帯の上下縁2列（必要なら中央1列）を持つ距離拘束メッシュで表す。

- 成分: 各節点の位置・速度・質量、長さ方向伸長、幅方向伸長、曲げ、ねじれ、接触。
- 変化: 切削が進むと刃先に新しい列を追加、生成部の頂点を刃の接触線に接続。帯が離れると拘束を解放。
- 重力: gをSI単位で使用（物体スケールの換算注意）。布ではなく野菜の薄片なので、曲げ剛性B・伸長剛性K・密度ρ・減衰を測定または資料から校正。
- 数値法: Verlet/PBDから小さく始め、拘束の硬さを安定して調整したい段階でXPBDを比較。布ライブラリを無理に導入する必要はない。
- 細く長くなるほど、節点数の無限増加を避ける。切削点近傍を精密、離れた帯は低解像度または静止メッシュへ移し、長期実行時に上限を設ける。
- 表示上の柔らかい揺れを採点に直結しない。実物の破断を力学モデルで評価するモードでは、必要に応じて帯の張力・ひずみのみ切削と結合する。

## 6. 破断（Phase R3）

「薄くむいたから一定確率で切れる」という方式は不採用。シートの位置ごとに厚み、切り込み欠陥、引張応力/ひずみ、曲げ曲率、ねじれを記録する。

候補条件：
- 引張: 幅W×厚さtの断面積に対する力の比から応力σ≈T/(W*t)を求め、材料の仮強度と比較。
- 曲げ: 薄い帯の表面曲げひずみε≈t*κ/2から負担を概算（κは曲率）。
- 欠陥: 刃が斜めに入り生じた切れ込みは、幅方向の局所接続や残断面を減らす。
- 裂け開始/伝播: 引張・曲げ・欠陥の組み合わせで閾値を超えた場所から亀裂を発生。部位ごとの材料強度を測定できなければ定量値は仮説と明示する。
- 破断イベントには、局所セル、厚み、局所張力、刃位置、最も寄与した要因を保存する。
- 摩擦や刃の食い込みによる「作業停止」と、剥けた帯が破れる「破断」は別イベント。

ガード：予告のないランダム切断を作らない。力学の係数を実測できない段階では、判定は「説明可能なゲーム近似」と区別して表示する。

## 7. 入力系・実物感

物理モデルが計算するのは手の押す力そのものではなく、大根と包丁の相対的な軌道。

- おためし: 大根回転自動、1指で刃の半径位置/傾き（簡略化）を動かす。物理の評価だけでなく、何を調整したか可視化。
- 道場: 左指で大根を回し、右指で刃の位置と上下滑走。位置入力の範囲・利得はデバイスDPRに依存しない。
- 上級: 傾きの微調整、上下ストロークのリズム、開始時の整形、刃の研ぎなど。
- UIと固定ステップシミュレーションを分離。端末のframe rateで結果が変わらない。
- 実機で指が画面を覆って接触点が見えない問題に対応して、操作域と観察域を分離する。

## 8. アーキテクチャ案

    src/physics/
      coordinate.js       // 単位、座標変換
      rigid-kinematic.js  // 大根と包丁の姿勢
      surface-grid.js     // 角度×幅の材料外表面と履歴
      collision.js        // 刃先と材料の接触・掃引
      removal.js          // 材料除去・体積と帯セグメントの生成
      force-model.js      // 切断抵抗・摩擦・回転失速
      ribbon-mesh.js      // 帯の生成・接続
      ribbon-solver.js    // 重力・曲げ・伸長 (PBD/XPBD)
      fracture.js         // 引張・欠陥・局所破断
      integrator.js       // 固定ステップ・サブステップ
      diagnostics.js      // 保存則、数値検算、パラメータ出典
    src/input/             // 制御入力
    src/view/              // 描画(最初はCanvas 2D)
    src/game/              // モード、評価、UI
    tests/physics/         // 解析解・収束・履歴・変形・破断

必須境界：physicsはブラウザDOM、Canvas、ビジュアル演出に依存しない。最初の検証時はNode.js標準テストランナーで十分。物理エンジンにユーザーの得点や解放条件を直接組み込まない。

## 9. 開発ゲートと成果物

**R0 形状と切削（最初の実装目標）**
- 円柱、刃先線、角度×幅フィールド、接触更新、実際に削れた局所体積、帯の上下厚さ履歴。
- 平行刃では上下同じ厚み。傾けると上下差が出る。停止・空振り・逆回転で材料は増えない。
- 初回剥きと2周目を分ける。厚さ・体積の保存則、格子解像度の収束が合格条件。

**R1 切削抵抗と角速度**
- 材料強度・刃先・摩擦・送りと切断力を結ぶ暫定式。
- ゲーム内パラメータと、実測済みの値とを表示・記録上で区別する。
- 入力不足なら失速、余裕があれば回転継続。正負の仕事・エネルギーの整合を検査。

**R2 帯の質量と柔軟性**
- 幅のある帯メッシュ生成、落下と曲げ、厚みによる重さ・しなりの違い、床/包丁との簡易接触。
- メモリ上限、FPS・物理時間刻みからの独立性を検査。

**R3 局所傷と裂け**
- 傾き・急な切り込み・薄さによる欠陥、張力と曲げに対応した裂け開始と伝播。
- 同じ入力ログは同じ時刻・場所で裂け、原因が説明できる。

**R4 測定・校正・実機受入**
- 実測報告の厚さ上端/下端、変動、長さ、所要時間で妥当性チェック。
- 可能なら教育者の協力のもと、動画から回転・刃運動・帯幅/厚みを測りモデルと比較。
- 危険な家庭での刃物実験を必須としない。力の実測が必要なら安全設備のある専門機関と協働する。
- iPhone Safari/Android Chrome/PCにて、操作感、性能、状態復元、中断、事故防止表現を検収。

各ゲートを終えてから次へ。フェーズの移行はモデル精度・性能・操作感の証拠で判断し、カレンダー上の期間だけで達成したとみなさない。

## 10. 物理テストに必須の性質

1. 材料半径・体積が不当に増えない（非破壊性、材料が自然回復しない）。
2. 空振り、停止、後退では材料除去がゼロ。
3. 平行刃で上下厚さがそろい、傾くと差が現れる。
4. 全周一様除去の円柱解析解と体積が一致。部分周の体積は角度区画で積分し、全周式を誤用しない。
5. 帯に生成した体積と大根から失われた体積が近似的に一致（許容誤差は解像度ごとに設定）。
6. 網目解像度を倍にすると計算が収束し、閾値に依存する結論を不当に反転させない。
7. 同じ操作記録・バージョン・刻み幅では計算結果が再現可能。
8. 30/60/120Hzの表示速度で切削結果が変わらない。
9. 破断箇所・原因とモデルの応力・欠陥計算が整合。
10. 大根/刃・帯/刃の接触が見た目だけの浮遊やすり抜けにならない。
11. 長い帯を切ってもメモリが無制限に増加しない。
12. 指を離す、画面を回転、タブを移る等で入力が暴走しない。
13. 校正した参考データの上下厚さ差・長さ/時間・バラツキは試験条件の誤差帯内に入る（目標誤差は計測手法と相談）。
14. 物性値の未校正の時点で「実測どおり」「料理の腕が上達する」と宣伝しない。

## 11. 根拠資料と解釈区分

S1 [桂むき実測研究] 加賀谷みえ子・加藤舞子（2023）『日本料理「桂むき」の剥き方技術に関する研究』椙山女学園大学研究論集54号、53-61。DOI: https://doi.org/10.20557/00003490 。熟練者1人と非熟練者6人、開始30cmの上下厚さと時間を記録。熟練者の平均厚さは約0.78mm、非熟練者の一例は約2.19mm。**厚さ分布の参照であって力・弾性率・破断強度の資料ではない**。小標本のため普遍的基準にしない。

S2 [指導者資料] 辻調理師専門学校：大根の桂むき https://www.tsuji.ac.jp/hp/gihou/japan/yasai/katura/katu.htm 。大根を回すこと、刃の上下運動、刃の安定と厚さの観察を定性的に参照。

S3 [野菜の切断研究] Singh, Das, Das（2016）, Effects of knife edge angle and speed on peak force and specific energy when cutting vegetables of diverse texture, International Journal of Food Studies, DOI https://doi.org/10.7455/ijfs/5.1.2016.a3 。角度・速度・野菜種が切断力とエネルギーに影響。**桂むきの大根固有の数値には流用不可**。

S4 [食品切断力学] Schuldt et al.（2018）, High-speed cutting of foods: Cutting behavior and initial cutting forces, Journal of Food Engineering. DOI https://doi.org/10.1016/j.jfoodeng.2018.02.024 。植物組織の切断挙動は一律な粘弾性体とみなせない点に注意。

S5 [XPBD原理] Macklin et al. (2016), XPBD Position-Based Simulation of Compliant Constrained Dynamics https://matthias-research.github.io/pages/publications/XPBD.pdf 。帯の形状拘束に適用する場合は原理を参照し、実物の野菜物性値は別に校正する。

## 12. 計画変更を要する判断

- 大根の表面格子だけでは刃の3D相互作用を表現できなければ、該当部分のみSDF/ボクセルへ拡張する。最初から高密度ボクセルは使用しない。
- 強制的なアニメーション補助で切削体積を変えない。簡単操作用の補助は入力層の規則として可視化。
- 切断力の実測値がない間は現実のN・J等の表示を禁じ、強弱の相対指標に限定。
- 物理モデルの改訂では既存の再生ログとのバージョン対応を保存し、無言で得点を上書きしない。
- 現行の data/simulation_presets.json はschema v1であり、target_thickness, depth等はゲーム用仮値。新しい校正パラメータは**別案として設計し**、承認された実装段階でschema移行・回帰試験を行う。
