# かつらむき道場 初期設計 v0.2

更新：2026-10-17 / 状態：設計・データ初稿、実装は未着手

## 目的

「大根を回し、包丁を動かす」という最小限の行為を、遊びながら上達できるWebゲームにする。上達に応じて包丁・料理・歴史を知れるが、ゲームの主役は桂むき操作のまま。

## 1. 30秒のゲームループ

道場に入る → モード選択 → 15〜60秒むく → 帯の長さ・厚さが変化 → 破断または終了 → 成績・根拠ある改善ヒント → もう一度。

結果は連続長・平均厚さ・厚さのばらつき・破断回数・食材使用量に分ける。最初から「薄さ」だけを競わせず、「均一な厚さで20cm続ける」を第一課題にする。

## 2. モード

- おためし（P0）：大根の回転は自動。指1本またはマウスで刃を調整。
- 道場（P0）：左手で大根を回し、右手で刃の送りを調整。二点タッチに対応。
- 無限（P1）：時間制限なしで連続むきを楽しむ。成績は練習系と分ける。
- お題（P1）：一定厚さ・一定長さなどを段階的に解放。
- 料理（P2）：できた帯から「けん」などの料理への利用を学ぶ。
- 包丁・歴史（P2）：図鑑形式で探索可能。プレイの邪魔をしない。

## 3. 入力モデル

スマホ：左画面の水平ドラッグ量で大根を回し、右画面の上下で刃のストローク、微小な左右移動で食い込みを調整する案。おためしは回転自動、右手だけで操作する。複数指入力の精度・疲労は実機で試す。

PC：左右/A・Dキーで大根を回し、マウス上下・左右で刃を動かす。反転・速度設定などは将来のアクセシビリティ候補。

## 4. 擬似物理（現実の切削物理ではない）

状態変数：radishAngle, remainingRadius, knifeStroke, bladeDepth, effectiveThickness, ribbonLength, tearRisk, edgeCondition。

基本更新：操作のΔangleから回転、刃の深さから帯の厚さ、回転半径×角度変化から帯の伸長距離を計算する。回転が止まる、刃が入りすぎる、厚みが急変する等がリボンの傷・破断へ反映される。失敗の説明は実際に記録した原因だけを表示する。

乱数で予告なく破断させない。調整数値はゲーム内単位であって実寸測定ではない。固定更新間隔と再現可能な操作ログを優先する。

## 5. 手触り・視覚と音

大根は円柱から徐々に細くなる。リボンは厚いと白く、薄くなると半透明に見える。切れた瞬間は連続音が止まり、リボンが揺れて落ちる。成功演出は大きくしすぎず、操作音と静かな光の変化を主役にする。

和紙・木を控えめに使う。外部の写真や市販デザインを無断転載しない。Canvas 2D・最小限の画像素材を優先。

## 6. 技法と知識の拡張

包丁：薄刃（関東型、鎌形）、菜切、三徳などを図鑑で比較。刃の特徴とゲーム係数は資料確認後に結び付ける。

料理：むいた帯の細切り・けん、巻物や飾りへの応用を紹介。完成料理ゲームに肥大化させない。

歴史：名称の語源として鬘帯・桂女・桂川の説を紹介し、**諸説であり断定できない**と明記。技法の最初の考案者は特定できない状態として扱う。

## 7. 技術と安全

HTML/CSS/JavaScript、Canvas 2D、Pointer Events。静的ホスティング候補はGitHub Pages。ログインや個人情報収集は設けない。設定と自己ベストは必要になった時点で端末内に限定。

実際の包丁の使い方をそのまま練習させる教材・安全保証にはしない。事故を招きうる実物動作を誘導するUI表現や、根拠のない技能認定を避ける。

## 8. MVPの合格条件

- 操作量の違いが帯の長さ・厚さへ再現可能に反映される。
- 意図的に無理な入力をした時の破断と原因説明が一致する。
- 片手モードがある。音OFF、reduced motionに対応できる。
- iPhone Safari、Android Chrome、PCブラウザで操作検証する（現時点未実施）。
- 1プレイは約30秒で終わり、すぐ再挑戦できる。
- 数値が現実の測定値でないことを表示する。
